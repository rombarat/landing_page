# Dukan: notes for future sessions

Multi-tenant Hebrew RTL store builder. Next.js 16 App Router + Supabase (Auth, Postgres with RLS, Storage). Read `AGENTS.md`: this Next.js version differs from older training data (`proxy.ts` instead of middleware, async `params`/`cookies()`, `revalidateTag(tag, profile)`). Its docs are in `node_modules/next/dist/docs/`.

## Non-negotiables

- **One codebase, one deployment.** Never generate code, repos, or deployments per merchant. A store is rows in the database.
- **Tenant isolation lives in Postgres.** Every tenant table has RLS keyed on `store_memberships` (`public.is_store_member`). Add RLS policies and explicit `grant`s in the same migration as any new table. `anon` gets no table grants; public data goes through `SECURITY DEFINER` functions that return only public fields.
- **Data access goes through `src/lib/db.ts`.** Use `asUser(claims, …)` for merchant work (RLS applies), `asAnon` for public functions, and `asService` only for `place_order` and platform-admin code, after `requirePlatformAdmin()`. Don't add a client-side Supabase data client.
- **Never trust client IDs.** Server actions get the store from the session (`merchantContext()` / `getMerchantStore`) and scope every query with `store_id = ${store.id}`, in addition to RLS.
- **Prices come from the database.** Orders are created only by `public.place_order` (service_role only, idempotent, rate-limited).
- **Trial and billing state is server-computed** (`account_entitlement`, `my_account_status`). Nothing marks an account paid except the audited admin action or a future verified billing webhook.
- **Never claim what didn't happen:** no "payment completed", no "message sent". Payment happens between merchant and customer.
- After any merchant mutation that affects the storefront, call `invalidateStorefront(slug)`.
- Migrations are append-only files in `supabase/migrations` (`YYYYMMDDHHMMSS_name.sql`). Run `npm run test:db` after schema changes.

## Design system

Platform identity: an Israeli market stall (דוכן). Tokens are in `src/app/globals.css` (`@theme`).

- Colors: ink `#1b1f3b` (text, dark surfaces), tchelet `#2d4bd1` (links, focus), turmeric `#f4b400` (primary buttons, ink text on it), paper `#fbfbf9`, line `#e3e3dd`. Status colors: olive, pomegranate, amber.
- Type: **Karantina** (`font-display`) for big headlines and numbers only; **IBM Plex Sans Hebrew** for all UI.
- Signature element: the `.price-tag` shape. Use it sparingly.
- Surfaces are flat with 1px borders (`Panel`). Shadows are reserved for floating things (`shadow-float`). Radius hierarchy: sm 6 / md 10 / lg 16 / xl 24.
- Avoid: one-word color accents in headlines, ALL-CAPS eyebrow labels, `A · B · C` meta strings, arrows appended to button text, decorative gradients, identical card grids with the same shadow, emoji icons (use lucide).
- Components: `src/components/ui` (`Button`/`LinkButton`, `Field` + `Input`/`Textarea`/`Select`/`Checkbox`, `Badge`, `Panel`, `Notice`, `EmptyState`, `Spinner`). Labels go above fields; errors are linked with `aria-describedby`.
- RTL: `<html lang="he" dir="rtl">`. Use logical utilities (`ms-`, `pe-`, `start-`, `text-start`). Wrap phone numbers, URLs, emails and slugs in `.ltr` (or `dir="ltr"` inputs). Format with `src/lib/format.ts` (`Intl`, `he-IL`, ILS, `Asia/Jerusalem`). Money is integer agorot.
- Copy: natural Hebrew, plain verbs, actions keep the same name through the flow (the "פרסום החנות שלי" button leads to a "באוויר" success screen). Errors say what happened and how to fix it.

## Storefront themes

Templates are configuration (`src/lib/themes.ts`): `boutique`, `artisan`, `bold`. They share one component set (`src/components/store`). They differ through `.tpl-*` rules in `store.css` and small layout branches. Merchant colors and font presets become `--st-*` CSS variables via `storeCssVars`. Add a template by extending `TEMPLATES`, the DB check constraint, and the `.tpl-*` CSS. Never copy components per template. Store fonts are self-hosted via `@fontsource` (`components/store/fonts.ts`).

## Local workflow

`npm run local:up` (Postgres + GoTrue + SMTP sink, no Docker) → `npm run dev`. Then `npm test`, `npm run test:db`, `npm run build && npm run test:e2e`. Fixture photos are generated by `npm run fixtures:images`. Marketing screenshots come from the real UI via `npm run marketing:capture`.
